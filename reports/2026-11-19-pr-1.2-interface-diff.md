# PR 1.2 接口 diff 草案：GithubForge、ticketCard、orchestrator_report

> 状态：**已实现（PR 1.2）**。PR 1.1（`ForgePort` 能力骨架）与 PR 1.2（GitHub Forge 适配 + 通用层切换）已落地；本文保留为接口记录。实际实现与草案的差异见文末 §9。
> 目标：GitHub 行为逐字节不变，但 `cards`/`tools`/`runtime`/`assessment` 不再直接 import `github-*`；为 GitLab 的 `change_number` / 宿主合并留出接口。

---

## 0. 一句话设计

- **`ForgePort` 是 Source 发布的“代码宿主能力”**：`GithubForge` 把现有 `github-pull`/`github-read` 包起来，不复制逻辑。
- **`ticketCard` 变成纯投影**：不再自己 import `pullOf`，由调用方传入 `TicketChange`（GitHub 输出仍是 `pr_number`，GitLab 输出 `change_number`）。
- **`orchestrator_report` 增加 `change_number`，保留 `pr_number` 别名**：内部通过 `host.changes.for(ticket)` 找到 Forge 与 `SourceContext`，再调 `forge.change.read/claim`。
- **`RepositoryRead` / `ChangeChecks` 接收 `Commands` 而不是 `SourceContext`**：因为 `MasterAssessor` 只有 `Commands`，没有完整 `SourceContext`。

  url: pull.html_url,
  authorId: pull.user.login,
  ...(pull.head.sha ? { headSha: pull.head.sha } : {}),
  ...(pull.head.ref ? { headBranch: pull.head.ref } : {}),

  ...(pull.merged_at ? { mergedAt: pull.merged_at } : {}),
  ...(pull.closed_at ? { closedAt: pull.closed_at } : {}),
  ...(pull.auto_merge != null ? { autoMerge: true } : {}),
})

    claim: (ctx, ticketId, change) => claimPull(ctx, ticketId, pullOfChange(change, ctx.deployment.repository)),
    observe: async (ctx, change) => observePull(ctx, pullOfChange(change, ctx.deployment.repository)),
    numbersOf: pullsOf,
    terminalNotices: (ctx, ticket, request) => pullEndNotices(ticket, request, ctx.deployment.repository),
  },
  checks: {
    read: (commands, change) => pullChecks(commands, change.headSha ?? ''),
    summary: (snapshot, where, resource) => ciSummary(snapshot as CiSnapshot, where, resource),
    fact: snapshot => ciFact(ciCounts(snapshot as CiSnapshot)),
  },
  repositoryRead: { read: (commands, path, kind) => readRepositoryPath(commands, path, kind) },
}

## 8. 需要你确认的 4 个点

1. **保留 `pr_number` 别名**：旧会话/旧测试继续可用；新字段 `change_number`。推荐保留。
2. **`ticketCard` 输出**：GitHub 仍 `pr_number`，GitLab 用 `change_number`；不改成统一 `change` 对象。推荐这样，改动最小。
3. **`notices` 是否传 change**：传了卡片更一致，但签名多一层；不传则 relay 里少编号。推荐传（`reportRelay`/`resultRelay` 各加一个可选参数）。

## 9. 实现偏差（实际落地时）

- `ChangeChecks.read` 接收 `signal` 但 GitHub 的 `pullChecks` 不消费信号；签名保留，供 GitLab 的 pipeline 读取使用。
- `DshExecutor` 的 `resultRelay` 调用（失败/等待等系统消息）暂未传 change，因此这些 relay 的 ticket card 不带编号；`orchestrator_report` 与终态事件已传。
- `ticketChange` 取“最后一个未关闭的变更，否则最后一个已关闭的”，与旧 `pullOf` 语义一致；`ticketCard` 仍对 GitHub 输出 `pr_number`，对 GitLab 输出 `change_number`。
- `GithubForge` 通过 `pullOfChange` 重建 `Pull`，只填 `claim`/`observe` 实际读取的字段；新增 `tests/github-forge.spec.ts` 覆盖解析、编号、终态通知，runtime 测试覆盖 `change_number` 的读/claim/绑定路径。
- `forgeFor` 对“Feishu 发起、无 follows”的 Ticket，在只安装一个代码宿主时回退到该宿主；安装多个代码宿主时仍以 `follows` 或 Origin Source 为准，避免猜错。
